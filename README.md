# АЗС-Пульт v2.1

Система управления ценами на топливо для сети автозаправочных станций: список станций, цены и продажи,
конкуренты, погода и трафик, аналитика, рекомендации по ценам с оценкой эффекта, загрузка CSV и ролевой доступ.

## Требования

| Компонент | Версия | Проверка |
|---|---|---|
| Node.js | 18+ | `node -v` |
| npm | 9+ | `npm -v` |
| PostgreSQL | 14+ (проверено на 18) | `psql --version` |
| Python | 3.9+ с pandas (только для пайплайна `_data/_BD/pipeline`) | `python -c "import pandas"` |
| bash | Git Bash или WSL (для `run_pipeline.sh`) | — |

Тесты интерфейса в режиме `jsdom` и тесты backend не требуют браузера.

## Быстрый старт

### 1. База данных

```bash
psql -h localhost -U postgres -c "CREATE DATABASE azs_pult;"
psql -h localhost -U postgres -d azs_pult -f _data/schema.sql
```

Тестовых пользователей (`admin`, `manager`, `analyst`, `viewer`) создаёт скрипт `backend/seed_users.py`
(пароль берётся из переменной окружения `DB_PASSWORD`). Пароли для разработки записаны в `CLAUDE.md`
и не должны попадать в боевую среду.

### 2. Backend

```bash
cd backend
cp .env.example .env        # задайте DB_PASSWORD и JWT_SECRET (не менее 32 символов)
npm install
npm run dev                 # http://localhost:3001, проверка: http://localhost:3001/health
```

Основные переменные (`backend/.env`):

| Переменная | Назначение |
|---|---|
| `DB_HOST`, `DB_PORT`, `DB_USER`, `DB_PASSWORD`, `DB_NAME` | подключение к PostgreSQL |
| `JWT_SECRET` | секрет для токенов, в продакшене — свой, длинный |
| `FRONTEND_URL` | адреса, с которых разрешены запросы (CORS) |
| `PG_DUMP_PATH` | путь к `pg_dump` той же версии, что сервер (для резервных копий) |

### 3. Frontend

```bash
cd frontend
cp .env.example .env.local  # при необходимости: VITE_API_URL
npm install
npm run dev                 # http://localhost:3000
```

Вход: `admin` / пароль из `CLAUDE.md`. Права по ролям описаны ниже.

### 4. Пересчёт рекомендаций

```bash
cd backend
npm run recommendations:generate
```

Команда пересчитывает рекомендации по всем станциям из `public.azs`. То же делает кнопка «Сформировать» на странице
рекомендаций и шаг 4c пайплайна. Ежедневный запуск в Windows можно настроить скриптом
`scripts/schedule-recommendations.ps1` (от имени администратора, вручную).

## Загрузка данных

Два способа:

1. **Через интерфейс:** раздел «Импорт». Принимаются CSV станций (`stations.csv`), цен и продаж, трафика,
   погоды, конкурентов, продаж магазина и акций. Новые станции из `stations.csv` появляются в пульте сами. После
   загрузки выполняются синхронизация таблиц приложения и пересчёт рекомендаций.
2. **Пересборка из папки с CSV:** пайплайн `_data/_BD/pipeline/run_pipeline.sh` (Git Bash или WSL):

```bash
cd _data/_BD/pipeline
export PGHOST=localhost PGUSER=postgres PGDATABASE=azs_pult
export PGPASSWORD='<пароль>'            # задаётся только в окружении, в файлы не записывается
export PG_DUMP="/c/Program Files/PostgreSQL/18/bin/pg_dump.exe"
bash ./run_pipeline.sh /путь/к/папке_с_csv
```

Пайплайн пересоздаёт схему `azs`, синхронизирует таблицы приложения в `public` (станции, цены, продажи, погода,
конкуренты) и пересчитывает рекомендации. Таблицы пользователей и журналов не меняются. Перед пересборкой сохраняется
резервная копия в `backups/` (последние 10 копий хранятся).

Пример папки с данными: `_data/backup_20261008_232028/_/` (7 CSV за 01.06.2025 – 21.09.2026).

## Режим моков

Интерфейс можно проверять без backend и базы:

```bash
cd frontend
npm run dev:mock -- --port 3002
```

Ответы берутся из `src/mocks/fixtures/responses.json`. Фикстуры — реальные ответы API, снятые с базы. Обновить их:
`node scripts/refresh-mock-fixtures.mjs` (при работающем backend). Записи в мок-режиме не сохраняются.

## Тесты

```bash
cd backend && npm test          # Jest: роли, синхронизация, импорт, аутентификация, формулы эффекта
cd frontend && npx vitest run   # Vitest + jsdom: store, мок-адаптер, экраны АЗС, аналитика, рекомендации
```

Проверка типов backend: `cd backend && npx tsc --noEmit`. Сборка фронтенда: `cd frontend && npm run build`.

Интеграционные тесты аутентификации работают с реальной базой (`DB_*` из `backend/.env`). Тестовые пользователи
с доменом `example.com` удаляются после каждого теста.

## Роли

| Роль | Доступ |
|---|---|
| admin | всё, включая расчёт по сети, администрирование, резервные копии |
| manager | управление своими станциями, импорт, отметка выполнения рекомендаций |
| analyst | аналитика и рекомендации, без изменения данных |
| viewer | просмотр станций и рекомендаций |

Роль проверяется по таблице `users` при каждом запросе (`requireRole`), а не по токену.

## Безопасность и секреты

- В репозиторий не попадают `.env`, резервные копии (`*.dump`, `backups/`), логи и `node_modules`. Правила — в `.gitignore`.
- Пароли БД передаются переменными окружения (`DB_PASSWORD`, `PGPASSWORD`). В скриптах нет значений по умолчанию.
- Тестовые учётные записи (`admin` и другие) предназначены только для разработки.
- Перед выводом в эксплуатацию: сменить `JWT_SECRET` и пароли, включить HTTPS, настроить CORS и резервное копирование
  (см. `docs/` и `development_report.md`).
