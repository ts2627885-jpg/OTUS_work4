# Отчёт о разработке АЗС-Пульт

Отчёт описывает работу над системой АЗС-Пульт v2.1 в одной сессии с ИИ-агентом (Claude Code). Состояние кода на
12.10.2026. Подробные тексты запросов — в `docs/PROMPTS.md`, журнал проблем и замеров — в `docs/REFACTORING_LOG.md`,
формулы правил — в `docs/RULES_FORMULAS.md`.

---

## 1. Описание процесса разработки

Работа шла этапами. Каждый этап начинался с запроса, в котором был конкретный результат и способ его проверить.

1. **Данные.** Проверка кодировок CSV, исправление проблем с Excel, замена названий станций и синтетических значений
   продаж в копиях и исходниках с сохранением счётчиков.
2. **База и пайплайн.** Пересборка схемы `azs` из CSV с резервными копиями, синхронизация схемы `public` (приложение),
   автоматический пересчёт рекомендаций, поддержка `stations.csv` при загрузке.
3. **Интерфейс.** Проверка станций и рекомендаций через кнопки, мок-режим для проверки отображения без backend,
   адаптивная вёрстка и таблицы-карточки.
4. **Тесты.** Jest на backend, Vitest с jsdom на frontend: позитивные сценарии, обработка ошибок, тесты компонентов.
5. **Рефакторинг.** Общая проверка ролей, кэш и переписанный запрос аналитики, чистый `tsc`, журнал и формулы правил.

Итог на момент отчёта: backend — 49 из 49 тестов, frontend — 21 из 21, `tsc` без ошибок, сборка проходит.

## 2. Применённые техники работы с ИИ

- **Конкретный критерий в запросе.** «Счётчики совпадают», «тесты проходят», «на 375 px без выхода за экран». Размытые
  запросы агент уточнял или сводил к проверяемым пунктам.
- **Измерять, а не угадывать.** Замеры эндпоинтов `curl`, таймеры внутри сервисов, `EXPLAIN` для SQL.
- **Сравнение до и после.** При переписывании SQL сверялись количество строк и суммы результатов старого и нового запроса.
- **Тесты, которые ловят расхождения.** Интеграционный тест нашёл, что код пишет в колонку `role_id`, которой нет в
  таблице `users`.
- **Фикстуры из реальных данных.** Моки сняты с работающего backend, поэтому форма ответов совпадает с кодом.
- **Проверка через браузер.** Headless Chrome делал снимки, агент смотрел PNG; для ширины 375 px использовался iframe,
  измерения `scrollWidth` и `getBoundingClientRect` проверяли выход за экран.
- **Вопрос пользователю там, где решение за ним.** Например, станции, созданные вручную, и пары «станция + топливо»
  без продаж.
- **Маленькие проверяемые шаги.** После каждого изменения — `tsc`, тесты, проверка эндпоинтов по ролям.

## 3. Примеры промптов и результатов

**Пример 1. Пайплайн и синхронизация.**
Запрос: «если появятся новые АЗС надо чтобы в пульте рекомендации и информация по новым АЗС выводилась автоматически».
Результат: шаг 4b (синхронизация `public` из `azs`, файл `sync_public.sql`) и шаг 4c (пересчёт рекомендаций). Проверено
пересборкой: все пять станций получили рекомендации.

**Пример 2. Адаптивность.**
Запрос: «таблицы сделать карточками».
Результат: `tableLabels.js` проставляет `data-label` из заголовков `<th>`, `responsive.css` превращает строки в
карточки до 768 px. Проверено снимками на 375 px: список станций, карточка станции, рекомендации.

**Пример 3. Производительность.**
Запрос: «оптимизировать производительность».
Результат: замеры показали, что `/api/analysis/rules` занимает 7 с. Основное время — запрос конкурентов с
коррелированными подзапросами. Переписан на соединение с агрегатом по диапазону дат. Время — 0,5 с, результаты совпали
(одинаковые суммы и количества).

**Пример 4. Тесты.**
Запрос: «создать автоматические тесты … исправить все найденные баги».
Результат: тесты нашли регистрацию с 500 (колонка `role_id`), потерянный текст ошибки входа (поле `message` вместо
`error`), зависимые интеграционные тесты и недетерминированный тест токена. Все исправлены, тесты проходят.

**Пример 5. Расчёт эффекта.**
Запрос: «как рассчитываются эффекты» и затем «добавить тест, который проверит расчёт эффекта на известных числах».
Результат: формула PRICE-001 вынесена в `priceGapEffect`, тесты на числах 2 ₽ × 1000 л × 0,5 = 1000 ₽/день и
другие.

## 4. Проблемы и их решения

| Проблема | Причина | Решение |
|---|---|---|
| Иероглифы в Excel | UTF-8 без BOM читается как cp1251 | Копии с BOM, исходники не меняли |
| Пайплайн падал на `promotions.csv` | В выгрузке нет колонки «Срок действия» | Колонка стала необязательной |
| Новая станция без продаж ломала синхронизацию | `fuel_types` = NULL | `COALESCE(..., '{}')` |
| Регистрация давала 500 | Код писал в `role_id`, в таблице роль текстом | Запись в `role` (найдено тестом) |
| Во фронтенде пропадал текст ошибки | Backend отдаёт `error`, код читал `message` | Чтение обоих полей |
| `[object Object]` в логах | Объект запроса передавался туда, где ждали строку | Исправлена сигнатура вызова |
| Прокси Vite на Docker-хост | Конфиг из Docker | `localhost:3001`, переопределение через переменную |
| 28 ошибок `tsc` | Типы не совпадали с данными и логгером | Типы приведены к реальным данным, `tsc` чистый |
| Тесты зависели друг от друга | Повторная регистрация логина в `beforeEach` | Очистка тестовых пользователей после каждого теста |
| Тест обновления токена падал | JWT с `iat` в секундах совпадал со старым | Пауза 1,1 с |
| Установка `jsdom` зависала | Реестр npm недоступен | Временно среда `node`; после восстановления — `jsdom` |
| Снимки при 375 px обрезались | Headless Chrome не уменьшает окно ниже ~500 px | Проверка внутри iframe 375 px и измерения |
| Аналитика 6–7 с | Коррелированные подзапросы | Соединение с агрегатом, кэш оценок |
| Повторяющаяся проверка ролей | Три копии с разным SQL | Общий `requireRole` и `UUID_RE` |
| Мок-фикстуры в production | Статический импорт адаптера | Ленивый `import()` |

## 5. Выводы и рекомендации

**Что сработало.** Проверяемые критерии в запросах, измерения до и после, тесты на ошибки (они нашли больше всего
реальных багов), снимки и измерения для адаптивности, фикстуры из реальных ответов API. Вопросы пользователю по
спорным решениям сэкономили переделки.

**Что стоило времени.** Проверка через headless-браузер (ложные снимки из-за минимальной ширины окна), сеть для
`npm` (установка прерывалась), расхождение документации и кода (`CLAUDE.md`, `QUICKSTART.md`, README с устаревшими
путями и Docker-настройками).

**Рекомендации.**
1. Решить, что делать со станциями, созданными вручную: синхронизация `public` их удаляет. Варианты: запретить ручное
   создание или сохранять такие станции при синхронизации.
2. Добавить тесты компонентов для админки и импорта, а также тесты на правила рекомендаций (сейчас проверяется только
   эффект PRICE-001).
3. Настроить ежедневный пересчёт через `scripts/schedule-recommendations.ps1` (запуск вручную от администратора).
4. Проверить интерфейс на настоящем телефоне: эмуляция ширины не покрывает сенсорный ввод и поведение браузера.
5. Сверить `docs/Error_Scenarios_Matrix.md` с кодом: часть сценариев (повторы с задержкой, опрос долгих операций,
   офлайн-кэш) описана как план и не реализована.
6. Обновлять мок-фикстуры скриптом `frontend/scripts/refresh-mock-fixtures.mjs` после заметных изменений данных.
7. Не хранить пароли в документации и в скриптах. Тестовые пароли из `CLAUDE.md` и `QUICKSTART.md` следует заменить,
   если проект выходит за пределы учебного окружения.
8. Перед production: сменить `JWT_SECRET`, включить HTTPS, настроить CORS и резервное копирование БД (см. `CLAUDE.md`).

**Ограничения отчёта.** Снимки экрана сделаны в headless Chrome, а не на устройстве. Тексты запросов в `PROMPTS.md`
восстановлены по памяти разговора и могут отличаться в деталях.
