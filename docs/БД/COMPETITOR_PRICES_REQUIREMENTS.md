## 📋 Требования к схеме БД

### Таблица: `competitor_price_history`

```sql
CREATE TABLE competitor_price_history (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    competitor_id UUID NOT NULL REFERENCES competitor(id),
    fuel_type_id UUID NOT NULL REFERENCES fuel_type(id),
    price_rub NUMERIC(10,2) NOT NULL,
    created_at TIMESTAMP WITH TIME ZONE NOT NULL DEFAULT CURRENT_TIMESTAMP,
    
    -- УНИКАЛЬНЫЙ CONSTRAINT на (конкурент, топливо, время)
    UNIQUE (competitor_id, fuel_type_id, created_at)
);

-- Индекс для поиска по времени
CREATE INDEX idx_competitor_price_history_created_at 
    ON competitor_price_history(created_at DESC);

-- Индекс для поиска по конкурентам
CREATE INDEX idx_competitor_price_history_competitor_id 
    ON competitor_price_history(competitor_id);
```

## 📊 Формат исходных данных (CSV)

**Файл:** `competitor_prices.csv`  
**Разделитель:** `;` (точка с запятой)  
**Кодировка:** UTF-8

### Структура колонок:

| Колонка | Формат | Пример | Обязательно |
|---------|--------|--------|-----------|
| `Название АЗС` | Text | АЗС 172 | ✅ |
| `Brand` | Text | Газпромнефть | ✅ |
| `Значение` | Number | 56.59 или 56,59 | ✅ |
| `Переменная` | Text | competitor_price_AI95_BREND | ✅ |
| `Временная метка` | DateTime | 01.01.2026_00:00:00 | ✅ |

### Правила валидации:

```
✅ Валидна цена:
  - От 0.01 до 99999.99 руб.
  - Может использовать запятую или точку как разделитель

❌ Отклоняется:
  - Цена = 0.00 (контрольное значение отсутствия данных)
  - Цена < 0 или > 100000
  - Невалидный формат числа
  - Пусто (NULL, пробел)
```

## 🔄 Логика преобразования типов топлива

### Маппинг из переменной к коду БД:

```python
Из переменной → К коду в БД

competitor_price_AI92           → AI92
competitor_price_AI92_BREND     → AI92_BIO (есть "_")
competitor_price_AI95           → AI95
competitor_price_AI95_BREND     → AI95_BIO (есть "_")
competitor_price_AI100          → AI100_BIO (только BIO)
competitor_price_AI100_BREND    → AI100_BIO
competitor_price_DT             → DT
competitor_price_DT_BREND       → DT_BIO (есть "_")
competitor_price_KPG            → KPG
competitor_price_SPG            → SUS (SPG → LPG)
competitor_price_SPG_BREND      → SUS
competitor_price_SUG            → SUS (SUG → LPG)
competitor_price_SUG_BREND      → SUS
```

**Правило:** Если в переменной есть `_` или `BIO` — это BIO вариант → добавить `_BIO` суффикс

## 📅 Формат временной метки

**Входящий формат:** `DD.MM.YYYY_HH:MM:SS`

```
Примеры:
01.01.2026_00:00:00  ← Полночь (дефолт, 88.8% данных)
01.08.2026_01:04:00  ← 1:04 ночи (реальное обновление)
01.08.2026_13:15:00  ← 13:15 дня (редко)
```

**Преобразование в БД:** 
```
DD.MM.YYYY_HH:MM:SS  →  YYYY-MM-DD HH:MM:SS

01.01.2026_00:00:00  →  2026-01-01 00:00:00
03.08.2026_01:04:00  →  2026-08-03 01:04:00
```

**Хранится как:** `TIMESTAMP WITH TIME ZONE` в UTC

## 🔐 Обработка конфликтов

**Стратегия:** `ON CONFLICT ... DO UPDATE`

Если цена за один и тот же компонент (конкурент, топливо, время) уже существует:
- ✅ Обновить цену на новое значение
- ✅ Сохранить timestamp создания первой записи

**SQL:**
```sql
ON CONFLICT (competitor_id, fuel_type_id, created_at) 
DO UPDATE SET price_rub = EXCLUDED.price_rub;
```
