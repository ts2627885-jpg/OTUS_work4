## 🎯 Обзор системы правил

### Назначение
Система правил определяет когда и как система должна генерировать рекомендации для оптимизации ценовой политики, управления трафиком и продажей товаров.

### Типы правил
- **Ценовые (PRICE-XXX)** — оптимизация цен на топливо
- **Трафиковые (TRAFFIC-XXX)** — управление потоком машин
- **Конкурентные (COMP-XXX)** — реакция на движения конкурентов
- **Промо (PROMO-XXX)** — планирование акций
- **Товаровые (SHOP-XXX)** — оптимизация магазина
- **Системные (SYS-XXX)** — операционные правила

### Жизненный цикл рекомендации
```
Генерация → Валидация → Приоритизация → Отфильтрование конфликтов → Отправка
```

## 💰 Правила ценообразования

### PRICE-001: Динамическое выравнивание цены с конкурентами

**Определение:**  
Если ваша цена отличается от средней цены конкурентов больше чем на `gapTol` ₽, система рекомендует выравнивание.

**Условие:**
```
ABS(your_price - competitor_median_price) > gapTol (дефолт: 0.5 ₽)
AND traffic_stable (изменение < trafficStable, дефолт: 10%)
AND no_recent_price_change (последняя смена > 24 часов)
```

**Действие:**
```
IF your_price > competitor_median_price + gapTol:
  recommendation = "Снизить цену на X ₽ до конкурентной"
  effect = (competitor_median_price - your_price) × volume × elasticity
  
IF your_price < competitor_median_price - gapTol:
  recommendation = "Поднять цену на X ₽"
  effect = (competitor_median_price - your_price) × volume × elasticity
```

**Формула эффекта:**
```
ΔRevenue = ΔPrice × Volume × (1 + Elasticity)
ΔPrice = |your_price - competitor_median_price|
Volume = средний объём за последние 7 дней
Elasticity = коэффициент эластичности для этого топлива
```

**Приоритет:**
- 🔴 **URGENT** если разрыв > 1.5 ₽
- 🟠 **HIGH** если разрыв 0.5-1.5 ₽
- 🟡 **MEDIUM** если разрыв 0.2-0.5 ₽

**Условия отмены:**
- Цена менялась < 24 часов назад (слишком частая смена)
- Трафик нестабилен (скачки > 10%)
- Разрыв объясняется погодой или праздником (внешний фактор)

---

### PRICE-002: Максимальная премия к цене

**Определение:**  
Система не рекомендует цену выше чем `maxPremium` ₽ от средней цены конкурентов (по умолчанию 0, т.е. не выше).

**Условие:**
```
your_price > competitor_median_price + maxPremium
AND volume_drop > 5% (за последние 7 дней)
```

**Действие:**
```
IF your_price > competitor_median_price + maxPremium:
  warning = "Вы дороже конкурентов на X ₽"
  recommendation = "Снизить цену или запустить промо"
  priority = HIGH
```

**Исключения:**
- Если доля заезда растёт → можно быть дороже
- Если ваша АЗС известна качеством → можно + 0.5 ₽
- Если конкурент временно снизил цену (< 3 дней) → игнорировать

---

### PRICE-003: Оптимальная цена на основе эластичности

**Определение:**  
На основе эластичности спроса система рассчитывает оптимальную цену максимизирующую выручку.

**Формула:**
```
Optimal_Price = Price_0 + ΔPrice
где ΔPrice максимизирует: Revenue = Volume × Price

Для линейной эластичности:
ΔPrice = -b / (2a)
где: Volume = a × Price + b (коэффициенты регрессии)

Практически:
- Если elasticity > -1: цена нечувствительна, можно повышать
- Если elasticity ≈ -1: нейтрально к цене
- Если elasticity < -1: цена очень чувствительна, не повышать
```

**Условие:**
```
model_reliability > 0.6 (R² > 0.36)
AND data_points > 20 (минимум 20 дней данных)
AND no_promotions_in_period (без акций на этот период)
```

**Действие:**
```
IF calculated_optimal_price > current_price:
  recommendation = "Поднять цену до X ₽"
  potential_effect = (optimal_price - current_price) × volume
  priority = MEDIUM
  
IF calculated_optimal_price < current_price:
  recommendation = "Снизить цену до X ₽ для максимума выручки"
  potential_effect = (optimal_price - current_price) × volume
  priority = LOW
```

---

### PRICE-004: Тест цены

**Определение:**  
Система рекомендует провести A/B тест цены если модель недостаточно надёжна.

**Условие:**
```
model_reliability < 0.6 (R² < 0.36)
OR data_points < 20
OR large_external_shocks (погода, праздник менял спрос)
AND traffic_stable
AND no_test_in_last_30_days
```

**Действие:**
```
recommendation = "Провести тест цены ±0.5 ₽ на 2-3 дня"
test_price_low = current_price - 0.5
test_price_high = current_price + 0.5

Результат теста:
- Если объём вырос > 5% при -0.5 ₽: провести снижение
- Если объём упал > 5% при +0.5 ₽: не повышать
- Если объём не изменился ±3%: цена оптимальна
```

**Приоритет:**
- 🟡 **MEDIUM** — информирующая рекомендация
- Тест не применяется в выходные и праздники

---

### PRICE-005: Защита от предельных цен

**Определение:**  
Система не рекомендует цены которые экономически нецелесообразны.

**Условие:**
```
new_price < cost_price + minimum_margin
```

**Действие:**
```
IF new_price < cost_price:
  error = "Убыточная цена! Не рекомендуется"
  priority = CRITICAL
  
IF new_price < cost_price + minimum_margin:
  warning = "Цена ниже минимальной маржи (X%)"
  priority = HIGH
```

**Параметры (по умолчанию):**
- `marginAI`: 6 ₽/л (для АИ-95)
- `marginDT`: 7 ₽/л (для дизеля)

## 🚗 Правила анализа трафика

### TRAFFIC-001: Падение доли заезда

**Определение:**  
Если доля заезда (л/машину) падает, это признак того что клиенты переходят к конкурентам.

**Условие:**
```
liters_per_vehicle_current < liters_per_vehicle_avg × (1 - captureTol)
где captureTol = 0.08 (8%)

AND this_change_not_explained_by:
- Погода (не было резких температурных скачков)
- Праздник (в день нет праздника)
- Дорожные работы (не закрывали дорогу)
```

**Действие:**
```
recommendation = "Падение доли заезда на X%"
root_cause = analyze_factors():
  - Ваша цена выше конкурентов? → PRICE-001
  - Конкурент рядом снизил цену? → COMP-001
  - У конкурента лучше сервис? → качественный (не в системе)
  - Погода изменилась? → внешний фактор

priority = HIGH (теряется объём)
effect = (expected_volume - actual_volume) × price
```

**Формула:**
```
Доля заезда = Средний объём (л) / Количество машин (ТС)
Expected = долгосрочная средняя
Trend = падение если < (долгосрочная * 0.92)
```

---

### TRAFFIC-002: Рост потока машин

**Определение:**  
Если поток машин растёт, это возможность увеличить выручку через оптимизацию цены.

**Условие:**
```
vehicle_count_current > vehicle_count_avg × (1 + trafficStable)
где trafficStable = 0.1 (10%)

AND price_competitive (ваша цена не выше конкурентов + 0.5 ₽)
AND capacity_available (станция не перегружена)
```

**Действие:**
```
IF traffic_growing AND price_optimal:
  recommendation = "Рост трафика на X% — возможность увеличить выручку"
  potential_effect = new_traffic_volume × (optimized_price - current_price)
  priority = MEDIUM
  action = "Удержать цену конкурентной, увеличить запасы топлива"
```

---

### TRAFFIC-003: Нестабильность данных трафика

**Определение:**  
Если данные счётчика трафика ненадёжны, система выдаёт предупреждение.

**Условие:**
```
traffic_sensor_reliability < 0.8
OR missing_data_percentage > 10%
OR data_variance > threshold (внезапные скачки)
```

**Действие:**
```
warning = "⚠️ Данные трафика ненадёжны (надёжность X%)"
recommendation = "Проверить счётчик ТС на АЗС"
priority = HIGH
impact = "Рекомендации на основе трафика могут быть неточны"
```

## 🔴 Правила управления конкурентами

### COMP-001: Срочная реакция на движение цены конкурента

**Определение:**  
Если конкурент неожиданно снизил цену, система рекомендует быструю реакцию.

**Условие:**
```
competitor_price_change < -compMove (дефолт: -0.4 ₽)
AND your_price > competitor_price + gapTol
AND change_detected_in_last_24_hours
AND volume_loss_detected (объём упал > 3%)
```

**Действие:**
```
recommendation = "Конкурент X снизил цену на Y ₽ — срочная реакция!"
options:
  1. Снизить свою цену на Z ₽ (выравнивание)
  2. Запустить мини-акцию (свободная альтернатива)
  3. Игнорировать если:
     - Его цена временная (< 3 дней)
     - У вас растёт объём (клиенты видят качество)
     - Позволяет маржа

priority = URGENT
ttl = 24 часа (если не решить, статус escalates)
```

**Алгоритм реакции:**
```
IF competitor_price < your_cost + margin:
  // Конкурент продаёт в убыток
  recommendation = "Не снижайте — конкурент неустойчив"
  wait_recommendation = 3-7 дней
  
ELSE IF competitor_price reasonable:
  reaction_time = 2-4 часа для максимального эффекта
  price_adjustment = competitor_price + 0.1 ₽ (немного выше)
  volume_recovery_expected = 60-80% за 24 часа
```

### COMP-002: Мониторинг цен конкурентов

**Определение:**  
Система отслеживает тренды цен конкурентов для прогнозирования их движений.

**Условие:**
```
new_competitor_price_data_available
```

**Действие:**
```
trend_analysis = linear_regression(competitor_prices_120_days)

IF trend_positive (цены растут):
  recommendation = "Цены конкурентов растут — можете повысить свою"
  
IF trend_negative (цены падают):
  recommendation = "Цены конкурентов падают — будьте готовы"
  
IF trend_volatile:
  recommendation = "Цены нестабильны — придерживайтесь конкурентной"
```

### COMP-003: Эластичность по конкурентам

**Определение:**  
Система анализирует как ваш объём реагирует на изменения цен конкурентов.

**Формула:**
```
Elasticity_to_competitor = ΔYour_Volume / ΔCompetitor_Price
Например: -0.5 означает что если конкурент повысит цену на 1 ₽,
ваш объём вырастет на 0.5%

Интерпретация:
- Elasticity < -1.0: Очень чувствительны к ценам конкурентов
- Elasticity -1.0 to -0.5: Нормально чувствительны
- Elasticity > -0.5: Слабо чувствительны (лояльность клиентов)
```

**Условие:**
```
IF elasticity_unknown (< 20 дней данных):
  priority = LOW
  recommendation = "Собирается информация для анализа"
  
IF elasticity_high (< -1.0):
  recommendation = "Вы очень чувствительны к ценам конкурентов"
  action = "Следить за конкурентами, быстро реагировать"
  
IF elasticity_low (> -0.5):
  recommendation = "Клиенты лояльны — можете быть дороже на 0.5-1 ₽"
  action = "Развивать качество, не гоняться за ценой"
```

## 🎉 Правила по промо-акциям

### PROMO-001: ROI акции

**Определение:**  
Система рассчитывает окупаемость каждой акции (скидки, бонусы).

**Формула:**
```
Cost_of_Promo = (discount_per_liter × volume_with_promo) + bonus_cost
Revenue_Gain = (additional_volume × price) - cost_of_promo
ROI = Revenue_Gain / Cost_of_Promo

Breakeven = Cost_of_Promo / (price - cost_price)
```

**Условие:**
```
IF ROI < 0:
  warning = "Акция убыточна — не рекомендуется"
  priority = HIGH
  
IF ROI >= 1 (окупается):
  recommendation = "Эта акция приносит прибыль — одобрено"
  priority = MEDIUM
  
IF ROI >= 2 (очень выгодна):
  recommendation = "Акция очень выгодна — рекомендуется"
  priority = HIGH
```

---

### PROMO-002: Планирование акций по календарю

**Определение:**  
Система предлагает проводить акции в дни когда спрос растёт естественно.

**Правило:**
```
days_of_week_effect = analyze_effect_of_day_of_week()

IF friday_to_sunday:
  natural_volume_boost = +20-30%
  promo_effect_expected = low (спрос уже высокий)
  recommendation = "Не запускайте акцию, предложение и спрос сбалансированы"
  
IF monday_to_thursday:
  natural_volume = baseline
  promo_effect_expected = high (есть место для роста)
  recommendation = "Хорошее время для акции"
  
IF holiday_period:
  natural_volume_boost = +40-60%
  recommendation = "Акция может быть неэффективна (спрос уже высокий)"
  alternative = "Лучше просто иметь товар в наличии"
```

---

### PROMO-003: Частота акций

**Определение:**  
Система ограничивает частоту акций чтобы избежать деградации бренда.

**Правило:**
```
IF promo_frequency > once_per_week:
  warning = "Слишком частые акции — клиенты привыкнут, маржа упадёт"
  recommendation = "Проводить максимум 1-2 акции в месяц на один товар"
  
IF promo_frequency = once_per_week:
  recommendation = "Оптимальная частота"
  
IF promo_frequency < once_per_month:
  recommendation = "Редкие акции более эффективны (привлекают внимание)"
```

## 🛍️ Правила по сопутствующим товарам

### SHOP-001: ABC-анализ товаров

**Определение:**  
Система определяет какие товары приносят основной доход и какие нужно развивать.

**Формула:**
```
ABC анализ по выручке:
A — 80% выручки (20% товаров) — ВЫСОКИЙ ПРИОРИТЕТ
B — 15% выручки (30% товаров) — СРЕДНИЙ ПРИОРИТЕТ
C — 5% выручки (50% товаров) — НИЗКИЙ ПРИОРИТЕТ

Примеры:
A: кофе, сигареты, напитки
B: снеки, мороженое, дорожная еда
C: сувениры, редкие товары
```

**Действие:**
```
FOR each_category in products:
  IF category in A:
    recommendation = "Это основной доход — поддерживать цену конкурентной"
    focus = price_optimization, inventory
    
  IF category in B:
    recommendation = "Потенциал роста — рассмотреть промо или лучшее размещение"
    focus = visibility, customer_acquisition
    
  IF category in C:
    recommendation = "Низкий вклад — можно сокращать объём"
    focus = efficiency, fast_moving
```

### SHOP-002: Ценовая чувствительность категорий

**Определение:**  
Система анализирует эластичность спроса по категориям.

**Условие:**
```
elasticity_of_category = (ΔQuantity / ΔPrice)

IF elasticity < -2.0:
  label = "HIGH_ELASTICITY"
  recommendation = "Клиенты очень чувствительны к цене"
  action = "Цену можно снижать для увеличения объёма"
  
IF -1.0 < elasticity < -2.0:
  label = "NORMAL_ELASTICITY"
  recommendation = "Нормальная чувствительность к цене"
  
IF elasticity > -1.0:
  label = "LOW_ELASTICITY"
  recommendation = "Клиенты слабо чувствительны к цене"
  action = "Можно повышать цену (это товары высокого спроса)"
```

### SHOP-003: Кросс-продажи

**Определение:**  
Система выявляет товары которые часто покупают вместе.

**Правило:**
```
IF customer_buys(fuel):
  probability_buys_coffee = 35%
  probability_buys_water = 25%
  probability_buys_snacks = 20%
  
recommendation = "Размещение кофе рядом с кассой увеличит продажи"
recommendation = "Предложить воду при покупке топлива"

IF coffee_price_high:
  recommendation = "Но не повышайте цену кофе — упадут сопутствующие покупки"
```

### SHOP-004: Рекомендация по марже категорий

**Определение:**  
Система рекомендует оптимальную маржу для каждой категории.

**Правило:**
```
optimal_margin = cost × (1 + elasticity_coefficient)

Примеры оптимальных марж:
- Кофе (низкая эластичность): 60-80% маржа
- Вода (высокая эластичность): 25-35% маржа
- Табак (регулируется): 10% маржа (в России)
- Сигареты (регулируется): 10% маржа

IF actual_margin < optimal_margin:
  recommendation = "Поднять маржу на X% — спрос позволяет"
  
IF actual_margin > optimal_margin:
  warning = "Маржа высока — можете потерять объём"
  recommendation = "Снизить цену для увеличения объёма"
```

## ⚙️ Правила операционные

### SYS-001: Окно анализа

**Определение:**  
Система работает с выбранным окном анализа для выстраивания рекомендаций.

**Допустимые окна:**
```
7 дней — краткосрочный анализ (тренды, реакция на конкурентов)
14 дней — среднесрочный анализ
28 дней (дефолт) — стандартный месячный цикл
56 дней — долгосрочный анализ (сезонность)
91 день — квартальный анализ
```

**Правило:**
```
IF window < 7 дней:
  warning = "Мало данных для надёжных рекомендаций"
  reliability = LOW
  
IF window = 7-14 дней:
  use_case = "Отслеживание быстрых изменений (реакция на конкурентов)"
  reliability = MEDIUM
  
IF window = 28 дней:
  use_case = "Планирование месячной стратегии"
  reliability = HIGH
  
IF window = 56-91 дней:
  use_case = "Анализ сезонности, долгосрочные тренды"
  reliability = HIGH
```

### SYS-002: Обновление расчётов

**Определение:**  
Система пересчитывает модели и рекомендации по расписанию.

**Правило:**
```
DEFAULT: Ежедневный пересчёт в 06:00 UTC+3 (9:00 МСК)

Для краткосрочного анализа (окно < 14 дней):
- Пересчёт каждые 4 часа (более актуальные рекомендации)
- Проверка на реакцию конкурентов каждый час

Для среднесрочного анализа (14-28 дней):
- Пересчёт ежедневно в 06:00

Для долгосрочного анализа (> 28 дней):
- Пересчёт раз в неделю (понедельник 06:00)

REAL-TIME мониторинг критических событий:
- Падение объёма > 20% → немедленное предупреждение
- Конкурент снизил цену > 1 ₽ → немедленное уведомление
- АЗС недоступна → критический alert
```

### SYS-003: Архивирование и история

**Определение:**  
Система сохраняет историю рекомендаций для аудита и анализа.

**Правило:**
```
Каждая рекомендация хранит:
- Дату создания
- Условия которые её вызвали
- Был ли совет выполнен
- Дату выполнения
- Фактический результат (если известен)

История хранится:
- 90 дней в активной БД
- 2 года в архиве (для анализа трендов)
- Более старое — в холодном хранилище

Анализ эффективности рекомендаций:
- Какие рекомендации приносили результат
- Какие игнорировались
- ROI каждого типа рекомендации
```

## 🎲 Система приоритизации

### Принцип приоритизации

Приоритет рекомендации определяется матрицей **Impact × Urgency**:

```
           Срочно (24ч)      Неспешно (7дн)    Плановое (30дн)
           
БОЛЬШОЙ    🔴 URGENT          🟠 HIGH           🟡 MEDIUM
ЭФФЕКТ     (+₽500+/день)      (+₽100-500/день)  (+₽10-100/день)

СРЕДНИЙ    🟠 HIGH            🟡 MEDIUM         🟢 LOW
ЭФФЕКТ     (+₽100-500/день)   (+₽10-100/день)   (+₽1-10/день)

МАЛЫЙ      🟡 MEDIUM          🟢 LOW            🟢 LOW
ЭФФЕКТ     (+₽10-100/день)    (<₽10/день)       (информирующие)
```

### Примеры приоритизации

**🔴 URGENT** (выполнить в течение 24 часов):
- Падение доли заезда > 10% (TRAFFIC-001)
- Конкурент снизил цену на > 1 ₽ (COMP-001)
- Цена выше конкурентов на > 1.5 ₽ (PRICE-001)
- Убыточные цены (PRICE-005)

**🟠 HIGH** (выполнить в течение недели):
- Падение объёма 5-10% (TRAFFIC-001)
- Разрыв цены 0.5-1 ₽ (PRICE-001)
- Очень выгодная акция (ROI > 2) (PROMO-001)

**🟡 MEDIUM** (выполнить в течение месяца):
- Проверить оптимальную цену (PRICE-003)
- Провести A/B тест цены (PRICE-004)
- Рост трафика (+5-10%) (TRAFFIC-002)
- Анализ потенциала товаров (SHOP-001)

**🟢 LOW** (информирующие, выполнить когда удобно):
- Тренды цен конкурентов (COMP-002)
- Сезонный анализ
- Долгосрочная стратегия

## ⚡ Конфликтующие рекомендации

### Принцип разрешения конфликтов

Когда несколько рекомендаций противоречат друг другу, система следует правилам разрешения:

### КОН-001: Цена vs Промо-акция

**Конфликт:**
```
Рекомендация 1: "Повысить цену на 1 ₽"
Рекомендация 2: "Запустить акцию со скидкой 0.5 ₽"
```

**Разрешение:**
```
ПРАВИЛО: Цена имеет приоритет
Действие: Выбрать повышение цены (прибыль выше)
Объяснение: Акция = экстренная мера, если цена не помогает
```

---

### КОН-002: Множественные рекомендации по одной АЗС

**Конфликт:**
```
Рекомендация 1: "Снизить цену АИ-95 на 0.5 ₽" (Priority: URGENT)
Рекомендация 2: "Повысить цену ДТ на 0.5 ₽" (Priority: HIGH)
Рекомендация 3: "Запустить акцию на АИ-95" (Priority: MEDIUM)
```

**Разрешение:**
```
Шаг 1: Выполнить по приоритету (URGENT → HIGH → MEDIUM)
Шаг 2: Проверить конфликты
  - Снижение АИ-95 + акция на АИ-95 = избыточно
    → Выбрать только снижение цены (дешевле и проще)
  - Повышение ДТ не конфликтует с остальным
    → Выполнить

Итоговые действия:
1. Снизить АИ-95 на 0.5 ₽ (URGENT)
2. Повысить ДТ на 0.5 ₽ (HIGH)
3. Пропустить акцию (разрешен конфликт)
```

---

### КОН-003: Реакция на конкурентов vs Маржа

**Конфликт:**
```
Ситуация: Конкурент снизил цену ниже себестоимости
Рекомендация системы: "Снизить цену и выровняться"
Здравый смысл: "Конкурент продаёт в убыток — ждать"
```

**Разрешение:**
```
ПРАВИЛО: Защита от убыточной цены (PRICE-005) имеет абсолютный приоритет
Действие: Не снижать цену ниже себестоимости + маржа
Вместо этого: Рекомендация "Игнорировать движение конкурента"
Объяснение: "Конкурент неустойчив, ждите 3-7 дней"
```

---

### КОН-004: Локальные vs Сетевые решения

**Конфликт:**
```
Для АЗС X: "Повысить цену на 1 ₽"
Для сети: "Средняя цена должна быть стабильна"
```

**Разрешение:**
```
ПРАВИЛО: Локальная оптимизация имеет приоритет
Действие: Разные АЗС могут иметь разные цены
Ограничение: Разница между АЗС одной сети < 1.5 ₽
  (чтобы клиенты не бросали одну АЗС для другой)

Пример приемлемого распределения:
АЗС в центре (высокий трафик): 50 ₽
АЗС на периферии (низкий трафик): 49.50 ₽
АЗС на автомагистрали (плено): 51 ₽
```

## 🔍 Примеры применения правил

### Пример 1: Критическая ситуация

```
СИТУАЦИЯ:
- Конкурент "Лукойл" рядом снизил цену на 1.5 ₽
- Ваш объём упал на 12% за 3 часа
- Ваша маржа позволяет снизить на 1 ₽

ПРАВИЛА:
- COMP-001: Срочная реакция на движение конкурента → URGENT
- TRAFFIC-001: Падение доли заезда → HIGH
- PRICE-001: Разрыв цены > 1.5 ₽ → URGENT

ПРИМЕНЁННЫЕ РЕШЕНИЯ:
1. Снизить цену на 1 ₽ (в течение 1-2 часов)
2. Отправить уведомление в Telegram менеджеру
3. Ждать восстановления объёма (прогноз: 3-6 часов)

РЕЗУЛЬТАТ ЧЕРЕЗ 2 НЕДЕЛИ:
- Если объём восстановился: решение правильное
- Если не восстановился: проверить конкурента (может быть АЗС лучше)
```

---

### Пример 2: Плановое повышение прибыли

```
СИТУАЦИЯ:
- Трафик растёт на +8% неделю за неделей
- Ваша цена ниже конкурентов на 0.3 ₽
- Маржа высокая (выше целевой на 1.5 ₽)
- Нет признаков нестабильности

ПРАВИЛА:
- TRAFFIC-002: Рост потока машин → MEDIUM
- PRICE-003: Оптимальная цена на основе эластичности → MEDIUM

ПРИМЕНЁННЫЕ РЕШЕНИЯ:
1. Провести A/B тест: поднять цену на 0.5 ₽ на 3 дня
2. Отслеживать объём и выручку
3. Если выручка выросла на 5-10%: оставить новую цену
4. Если объём упал > 10%: вернуться к старой цене

РЕЗУЛЬТАТ:
- Прибыль выросла на 7-12% без потери объёма
- Маржа оптимизирована
- Клиенты остались довольны (ненастойчивая аЗС)
```

### Пример 3: Конфликтующие рекомендации

```
СИТУАЦИЯ:
День: Среда вечер (пик спроса)
Конкурент: Запустил скидку 2 ₽ на кофе
Ваша АЗС: Только что открыта (1 неделя)

РЕКОМЕНДАЦИИ:
1. PROMO-002: Плохое время для акции (спрос уже высокий)
2. COMP-001: Конкурент снизил цену — реагировать
3. SYS-001: Новая АЗС нужна приватизация клиентов

РАЗРЕШЕНИЕ КОНФЛИКТА:
Приоритет 1: Привлечение клиентов на новую АЗС (это более важно)
Приоритет 2: Реакция на конкурента вторична (у вас нет истории)

ДЕЙСТВИЕ:
- Не следить за ценой конкурента пока не установите свою базу клиентов
- Запустить собственную «Welcome» акцию (скидка 1-1.5 ₽ на неделю)
- Через 1-2 недели переходить на конкурентный мониторинг

РЕЗУЛЬТАТ:
- Клиентская база создана
- Лояльность выше (помогла акция на начальном этапе)
- Теперь можно оптимизировать цены
```
