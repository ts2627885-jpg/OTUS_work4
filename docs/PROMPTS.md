# Промпты, которые использовались при работе с ИИ-агентом

Документ дополняет `docs/REFACTORING_LOG.md`. Здесь — тексты запросов в том виде, в каком они ставились (на русском),
и ход отработки по каждой группе. Короткие реплики («продолжай», «ХОРОШО», «2») приведены в хронологии, но без
пояснений: их смысл был понятен из предыдущего шага.

Общее правило запросов: задача ставилась как конкретный результат, а проверка — как измеримый критерий.

## 1. Данные и кодировки

**Запрос:** «проверь кодировку файлов в папке azs-pult-fullstack\_data\backup_20261008_232028\_\»
**Ход:** проверка BOM, строгое декодирование UTF-8, окончания строк по всем 7 CSV. Результат: все файлы — корректный
UTF-8; различия в BOM и смешанные окончания строк в `promotions.csv`.

**Запрос:** «в excell если открывать иероглифы выводит»
**Ход:** причина — UTF-8 без BOM читается Excel как cp1251. Решение: копии в `_excel/` с BOM, исходники не менялись.

**Запрос:** «в файлах АЗС172 и АЗС 172 замени на АЗС121 и АЗС 121 … (далее пять пар)»
**Ход:** замены во всех файлах копии `_excel`, проверка счётчиков и отсутствия старых кодов. Затем отдельным запросом —
коды вида «Запад-МФ-6910172», и отдельно — «Татнефть-АЗС-Запад → сеть АЗС» в `promotions.csv`.

**Запрос:** «в файле shop_sales.csv там где продажи по датам замени новыми синтетическими данными, если стоял ноль, то
оставь как было в ячейке»
**Ход:** синтетика по строке с сохранением нулей; исходник сохранён в scratchpad для отката.

**Запрос:** «в файле prices.csv замени значения объемов продаж по видам топлива», затем «нулевые значения тоже стали
синтетическими»
**Ход:** сначала — ненулевые; после вопроса о парах без продаж пользователь выбрал «оставить как есть», нули там, где
топлива нет, сохранены.

## 2. База данных и пайплайн

**Запрос:** «как обновить данные в бд» → «надо удалить старые данные в бд и загрузить новые из …»
**Ход:** пересборка схемы `azs` пайплайном с резервной копией. Найдено расхождение: промо-колонка «Срок действия»
отсутствует в выгрузке — сделана необязательной.

**Запрос:** «а в АЗС пульт старые данные» → «а в новых файлах новые АЗС. Старых нет» → «не должно быть»
**Ход:** синхронизация схемы `public` из `azs` (`sync_public.sql`) и шаг 4b пайплайна.

**Запрос:** «если появятся новые АЗС надо чтобы в пульте рекомендации и информация по новым АЗС выводилась автоматически»
**Ход:** шаг 4c пайплайна — пересчёт рекомендаций по всем АЗС из `public.azs`.

**Запрос:** «а можно сделать по нажатию кнопки формировать рекомендации и проверку имеющихся АЗС»
**Ход:** endpoint `GET /api/stations/check` и кнопка «Проверить АЗС» на странице рекомендаций.

**Запрос:** «а при загрузке новых csv файлов при появлении новых АЗС они появятся на пульте» → «делать»
**Ход:** поддержка `stations.csv` в загрузке, синхронизация после каждой загрузки, сообщение о новых станциях в ответе.

**Запрос:** «надо чтобы все обновлялось при загрузке новых csv, обнови md»
**Ход:** проверено на загрузке `weather_data.csv` и станции из `stations.csv`; обновлены `DATA_LOADED.md` и структура
backup.

## 6. Адаптивность: итерации

1. **Первый снимок** (Chrome headless, 375 px): таблицы и панели выходят за экран; подтверждено на списке станций,
   карточке и дашборде.
2. **Ложная тревога.** Снимки обрезались не из-за вёрстки, а потому что headless Chrome не уменьшает окно ниже ~500 px.
   Исправлено: проверка внутри iframe шириной 375 px.
3. **Первое исправление** (`responsive.css`): `min-width: 0` основной колонки, прокрутка таблиц внутри блока,
   переносы шапок и фильтров, одна колонка для форм на 480 px.
4. **Проверка через измерения:** `scrollWidth`, `getBoundingClientRect`, выход элементов за пределы окна вне
   прокручиваемых контейнеров. Страница не выходила за экран.
5. **Таблицы карточками:** наблюдатель `MutationObserver` проставляет `data-label`; CSS превращает строки в карточки.
6. **Выравнивание значений:** длинный текст переведён на выравнивание по левому краю.
