# Расчёты АЗС-Пульт: что считается, по каким данным и с какими ограничениями

Документ описывает состояние расчётов по коду (`backend/src/services/rules*.ts`, `elasticity.service.ts`,
`analytics.service.ts`, `routes/dashboard.routes.ts`). Пороги и окна меняются во вкладке
«Администрирование → Настройки расчёта». Исходные правила: `docs/AI_Agent_Rules.md`.

## 1. Правила рекомендаций, которые считаются

| Правило | Что считается | Ограничения |
|---|---|---|
| PRICE-001 | разрыв нашей цены с медианой конкурентов (окно `comp_window_days`) | приоритет URGENT при разрыве больше `price_gap_urgent` |
| PRICE-002 | премия к конкурентам при падении объёма (порог `premium_drop_pct`) | |
| PRICE-004 | одна сводная рекомендация PRICE-004-SUMMARY по всем парам станция–топливо, где эластичность не значима; в причине перечислены пары и их причины (мало данных / цена почти не менялась / эффект не отличим от нуля) | сетевой вариант NET-TEST-* для ненадёжных топлив; тест предлагается, только если у пары есть вариация цены |
| COMP-001 | снижение цены конкурента на 0.4 ₽ и более с падением объёма ≥30% | расстояние до конкурента не заполнено, порог 500 м не проверяется |
| COMP-002 | тренд цен конкурентов по неделям | R² > 0.5, минимум 12 недель, порог 0.5% в неделю, не менее двух брендов в одну сторону, 95%-интервал по бутстрапу (500 повторов) не содержит ноль |
| COMP-003 | эластичность объёма к медиане цен конкурентов (OLS по ln, дни недели, n ≥ 60) | значима при \|t\| ≥ 2 |
| TRAFFIC-001 | падение доли станции в объёме сети на 8% и более за 28 дней | прокси: рынок не измерен, сравнение только с сетью |
| TRAFFIC-002 | рост или падение трафика (станция и сеть) | трафик есть только с 10.02.2026 |
| TRAFFIC-003 | средние легковые машины станции меньше 20% медианы или меньше 25 дней покрытия | выявляет проблемы данных, а не качество датчиков |
| PROMO-002 | дни недели, где объём сети ниже 85% среднего за 180 дней | описательное правило |
| PROMO-003 | частота акций по сети | учитывает все акции из выгрузки |
| SHOP-001 | ABC-анализ товаров магазина по выручке | |

Сетевые варианты (`Вся сеть`): PRICE-003 по сетевой эластичности по каждому топливу, NET-TEST для ненадёжных топлив,
TRAFFIC-002 по сети, PROMO-003 по сети.

## 2. Эластичность спроса

- Панельная оценка: ln(объём) на ln(цену), фиксированные эффекты станций, день недели ISO (из даты, не из поля `day_of_week`),
  праздник, месяц (только для окон от 180 дней).
- Нерабочие дни исключаются: суточный объём станции ниже 10% её медианы.
- Колонки без вариации удаляются. Если цена почти не менялась (разброс внутри станции < 0.02), оценка не считается.
- Значимость: |t| ≥ 2. Оценка без значимости в рекомендациях не используется как основание для изменения цены.
- В таблице цен и в симуляторе показывается 95%-интервал: e ± 1.96·se, умноженное на изменение цены. Прогноз без интервала не выводится.
- Вкладка «Трафик»: станция с легковыми ниже 20% медианы или с менее чем 25 днями данных помечается в колонке «Пометка».
- Для станции берётся её оценка; если она не значима, используется сетевая.

## 3. Панель «Пульт» (`/api/dashboard`)

- Окно 7, 14, 28, 56 или 91 день; день анализа не позже последнего дня данных.
- Считается: объём, изменение объёма, изменение без первых 14 дней после старта акции, число акционных дней,
  позиция цены (наша цена минус медиана конкурентов за 14 дней), трафик и его изменение, доля заезда (литров на легковую машину)
  и изменение доли, эффект осадков.
- Эффект осадков показывается, только если он значим по регрессии за год с поправками (день недели, месяц, праздник, станция, акции).
  Сейчас значимых эффектов нет, в таблице стоит «—».
- Срочные рекомендации: до 5 самых приоритетных активных рекомендаций (по приоритету, затем по дате).

## 4. Аналитика по вкладкам

- Цены, конкуренты, трафик, факторы, объём, магазин, акции — описаны в коде `analytics.service.ts`.
- Вкладка «Акции»: сравнение среднего объёма сети до и после старта (окно 7, 14 или 28 дней), с поправкой на день недели и праздники.
  Сезонная поправка через прошлый год не выполняется: в данных нет периода до 1 июня 2025 года.
- Акции сравниваются во времени, контрольной группы нет, причинность не доказана.

## 5. Что не считается

| Правило | Причина |
|---|---|
| PRICE-003 на уровне станции | нет себестоимости (сетевой вариант считается) |
| PRICE-005 (цена ниже себестоимости) | нет себестоимости |
| PROMO-001 (ROI акций) | нет скидок, стоимости акций и прироста по ним |
| SHOP-002 (маржа по товарам) | нет маржи по товарам |
| SHOP-003 (перекрёстные продажи) | нет данных о чеках |
| SHOP-004 (ассортимент конкурентов) | нет данных об ассортименте конкурентов |

Этот список выводится в интерфейсе «Рекомендации» из `notComputed` в `rules.service.ts`.

## 6. Ограничения данных (проверено)

- Трафик есть только с 10.02.2026. У станции 603 около 540 машин в день при 3 800–10 000 на других станциях.
  По решению владельца данные оставлены, помечены правилом TRAFFIC-003.
- Дизель на станциях 172 и 606 заметно выше остальных (около 46 тыс. и 34 тыс. литров в день). Подтверждения, что это трасса, нет.
- Поле `day_of_week` в исходном календаре ошибочно; все расчёты используют ISO-день недели из даты.
- Расстояние до конкурентов в данных не заполнено.
- Эластичность значима только для AI-92 на сетевом уровне (около −2.8) и для конкурентной эластичности станции 604.
  По остальным парам станция–топливо оценки не значимы.

## 7. Когда запускаются расчёты

- **Рекомендации** пересчитываются в двух случаях: при нажатии «Сформировать» (только admin, `POST /api/recommendations/generate`)
  и автоматически в конце каждого успешного импорта CSV (`importCsv` → `generateRecommendations`). Ошибка пересчёта не отменяет импорт:
  она возвращается в поле `recommendations.error` ответа импорта и пишется в журнал.
- Логика сохранения вынесена в `backend/src/services/recommendations.service.ts`. Активные рекомендации обновляются по `dedupe_key`,
  устаревшие закрываются как `rejected`.
- **Аналитика, «Пульт», «Анализ правил»** пересчитываются на каждый запрос и ничего не сохраняют.
- Пересборка схемы `azs` (`run_pipeline.sh`) рекомендации не пересчитывает: запускайте импорт или «Сформировать» после неё.
- Расписания (cron) нет.

## 8. Проверка доступа по ролям (API, 09.10.2026)

| Раздел | admin | manager | analyst | viewer |
|---|---|---|---|---|
| `/api/dashboard` | 5 станций | 5 станций (назначены все 5, 09.10.2026) | 5 | 5 |
| `/api/azs` | 5 | 5 | 5 | 5 |
| `/api/recommendations` | 33 активных | 33 | 33 | 33 |
| `/api/analytics/*` | доступ | доступ | доступ | доступ |
| `/api/analysis/rules` | доступ | доступ | доступ | доступ |
| `/api/admin/users`, `/api/admin/logs/login` | доступ | 403 | 403 | 403 |

Генерация рекомендаций доступна только admin (`requireRole(['admin'])`). Выполнение рекомендации — admin и manager (сетевые — только admin).
Управление станциями: создание и удаление — admin; редактирование — admin или manager с доступом к станции.

Фронтенд (`stores/auth.js`): экран «Рекомендации» требует `recommendations_view` (есть у manager, analyst, viewer);
«Пульт» и «Аналитика» доступны всем авторизованным; «Администрирование» требует `users_manage` или `settings` (только admin).

Менеджеру `manager` назначены все 5 станций через `PUT /api/admin/users/:id/azs`. Чтобы убрать или сузить доступ, используйте «Администрирование → Пользователи».
