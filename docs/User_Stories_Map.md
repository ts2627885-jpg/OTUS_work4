# 👥 PERSONAS

## Persona #1: Роман (Roman) - Менеджер АЗС

**Профиль:**
- **Возраст:** 35-45 лет
- **Опыт:** 8+ лет управления АЗС
- **Техническая грамотность:** Средняя (может пользоваться Excel, разбирается в основах)
- **Цель:** Максимизировать прибыль АЗС, реагировать на конкурентов, контролировать персонал
- **Главные болевые точки:** 
  - Не знает оптимальную цену на топливо
  - Конкурентов сложно отслеживать вручную
  - Нужны данные для решений в реальном времени

**Мотивация:** Увеличить выручку АЗС на 5-10% за счет оптимизации цен

**Техническое окружение:**
- Пользуется: ПК (Windows/Mac), иногда мобильный
- Время в системе: 1-2 часа в день
- Действия: Проверка цен, применение рекомендаций, просмотр отчетов

---

## Persona #2: Анна (Anna) - Финансовый аналитик сети

**Профиль:**
- **Возраст:** 28-35 лет
- **Опыт:** 5+ лет финансового анализа, работала с BI-инструментами
- **Техническая грамотность:** Высокая (SQL, Python, Tableau)
- **Цель:** Анализировать данные по всей сети, находить тренды, оптимизировать стратегию
- **Главные болевые точки:**
  - Данные разрозданы по разным источникам
  - Нужна глубокая аналитика и прогнозы
  - Сложно отслеживать эффект от решений

**Мотивация:** Получить единую платформу для анализа данных, найти паттерны и возможности оптимизации

**Техническое окружение:**
- Пользуется: ПК (Linux/Mac), писать скрипты на Python
- Время в системе: 3-4 часа в день
- Действия: Углубленный анализ, экспорт данных, создание отчетов

# 🗺️ USER JOURNEYS

## User Journey #1: Роман (Manager) - "Оптимизация цены за 30 минут"

```
ПЕРСОНАЖ: Роман, менеджер АЗС #42
ЦЕЛЬ: Проверить рекомендации по цене и применить оптимальную цену
ВРЕМЯ: Утро, 09:00, перед сменой
```

### Happy Path (Счастливый путь)

```
1. ВХОД В СИСТЕМУ
   Роман приходит на работу, открывает браузер → заходит в систему через логин/пароль
   ✅ Видит Dashboard с рекомендациями для его АЗС

2. ПРОСМОТР РЕКОМЕНДАЦИЙ
   На Dashboard видит карточку "Цена выше рынка на ₽0.6"
   Нажимает на карточку "Выравнивание цены"
   ✅ Видит деталии: текущая цена 55.5₽, рекомендуемая 54.9₽, эффект +₽240/день

3. ПРОВЕРКА КОНКУРЕНТОВ
   Видит сравнение цен конкурентов (таблица с 5 ближайшими конкурентами)
   ✅ Все данные актуальны (обновлены 10 минут назад)

4. ПРИМЕНЕНИЕ РЕКОМЕНДАЦИИ
   Нажимает кнопку "Применить рекомендуемую цену 54.9₽"
   ✅ Видит подтверждение: "Цена успешно обновлена"
   ✅ На станции автоматически обновились табло

5. ЗАВЕРШЕНИЕ
   Видит уведомление об успешном изменении
   ✅ Может вернуться на Dashboard или посмотреть другие рекомендации
```

### Нормальный сценарий с проверками

```
ШАГ 2 ВАРИАНТ A: Роман сомневается в рекомендации
- Нажимает "Показать подробный анализ"
- Видит: формула расчета, R² модели, диапазон уверенности
- Решает применить рекомендацию или ждать более уверенного предложения

ШАГ 3 ВАРИАНТ B: Конкурент изменил цену только что
- Видит красное уведомление "Конкурент XX изменил цену"
- Может расширить конкурентов на странице (показать еще 5)
- Пересчитывает рекомендацию в уме или просит систему

ШАГ 4 ВАРИАНТ C: Роман хочет выбрать другую цену
- Вместо кнопки "Применить" вводит собственную цену в поле
- Видит прогноз эффекта для этой цены
- Применяет и сохраняет как "Собственная стратегия"
```

### Edge Cases (Проблемные сценарии)

```
❌ ПРОБЛЕМА 1: Интернет отключился
   → Видит оффлайн-уведомление
   → Может работать с закешированными данными (1 час назад)
   → Синхронизируется при восстановлении связи

❌ ПРОБЛЕМА 2: Цена ниже себестоимости
   → Видит КРИТИЧНОЕ красное уведомление
   → Кнопка "Применить" ЗАБЛОКИРОВАНА
   → Текст: "Цена не может быть ниже себестоимости (52₽)"
   
❌ ПРОБЛЕМА 3: Нет прав на изменение цены
   → Видит рекомендацию, но кнопка "Применить" disabled
   → Текст: "Требуются права Manager. Отправить заявку директору?"
```

## User Journey #2: Анна (Analyst) - "Глубокий анализ тренда цен"

```
ПЕРСОНАЖ: Анна, аналитик данных
ЦЕЛЬ: Проанализировать данные по 50 АЗС за квартал, найти паттерны
ВРЕМЯ: 2 часа анализа
```

### Happy Path

```
1. ВХОД И ФИЛЬТРАЦИЯ ДАННЫХ
   Заходит на Analytics раздел
   Выбирает фильтры: Дата (Q3 2026), АЗС (регион: "Тверская область"), Метрика (Цена, Объем)
   ✅ Видит таблицу с 50 АЗС, их ценами и объемами за 90 дней

2. ВИЗУАЛИЗАЦИЯ
   Переключается на вид "Граф" (График)
   Видит 3 линии: средняя цена, мин/макс диапазон, объем продаж
   ✅ Четко видны тренды, сезонность, выбросы

3. ЭКСПОРТ И РАСЧЕТЫ
   Нажимает "Экспортировать" → скачивает CSV
   Открывает в Python: строит свою модель, считает корреляции
   ✅ Находит сильную корреляцию между объемом и средней ценой в регионе

4. СОЗДАНИЕ ОТЧЕТА
   Создает новый отчет "Q3 Анализ ценовой стратегии"
   Добавляет: графики, таблицы, выводы, рекомендации
   Сохраняет как PDF и делится с директором
   ✅ Директор видит отчет и принимает решение

5. ОТСЛЕЖИВАНИЕ РЕЗУЛЬТАТА
   Через неделю смотрит на метрику "Средний доход по сети"
   ✅ Видит прирост на 3% → рекомендация сработала!
   Добавляет это в следующий отчет как evidence
```

### Сложный сценарий

```
ЗАДАЧА: Найти АЗС которые работают "неоптимально" (низкая цена при высоком спросе)

ШАГИ:
1. Фильтрует: Traffic > median AND Price < median для каждого региона
2. Видит 5-7 АЗС которые "оставляют деньги на столе"
3. Кликает на каждую: видит почему (старые данные? другая стратегия?)
4. Создает Report с выводом: "Потеря ₽500k/месяц из-за недооценки на 5 АЗС"
5. Делится с manager's этих АЗС
6. Через неделю видит что они приняли рекомендацию → +₽120k в этом месяце
```

## User Journey #3: Сергей (Admin) - "Импорт данных из CSV"

```
ПЕРСОНАЖ: Сергей, администратор
ЦЕЛЬ: Загрузить месячный файл с историческими данными (50k строк)
ВРЕМЯ: 30 минут с мониторингом
```

### Happy Path

```
1. ВХОД В АДМИН-ПАНЕЛЬ
   Заходит через специальный URL с повышенными правами
   ✅ Видит админ-меню: Users, Data Import, System Status, Logs

2. ЗАГРУЗКА ФАЙЛА
   Нажимает "Data Import" → "Загрузить CSV"
   Выбирает файл: sales_2026_09.csv (50k строк, 12MB)
   ✅ Видит preview: первые 10 строк, валидация успешна

3. КОНФИГУРАЦИЯ МАППИНГА
   Видит предложенное маппирование колонок (автоматическое)
   Проверяет: date_column → created_at, price → price_per_liter (Correct!)
   ✅ Может отредактировать если нужно

4. ЗАПУСК ИМПОРТА
   Нажимает "Импортировать"
   Видит прогресс-бар: "Обработано 0/50000..."
   ✅ Каждые 5 сек видит обновление: 5000, 10000, 25000...

5. ЗАВЕРШЕНИЕ
   Видит итоговый отчет:
   - Успешно импортировано: 49,987 строк
   - Ошибок (пропущено): 13 строк (детали в отчете)
   - Время выполнения: 45 сек
   - Дата добавления: 2026-10-07 11:30:00
   ✅ Данные доступны в системе

6. ПРОВЕРКА
   Видит в логах: "Import completed successfully by admin@company.com"
   Может скачать отчет об ошибках (невалидные строки)
   Исправляет 13 ошибочных строк, перезагружает
   ✅ Все 50k строк теперь в базе
```

### Сценарий с проблемами

```
❌ ПРОБЛЕМА: Файл 200MB, система предупреждает
   → Видит сообщение: "Большой файл, рекомендуем разбить на части (max 50MB)"
   → Разбивает на 4 файла, загружает по одному

❌ ПРОБЛЕМА: В файле неверный формат даты
   → Видит ошибку: "Ошибка в строках: 1245, 3456, 8901"
   → Детали: "Ожидается YYYY-MM-DD, получено DD.MM.YYYY"
   → Может скачать CSV ошибочных строк, исправить, переименить
   → Перезагружает исправленный файл

❌ ПРОБЛЕМА: Дублиующиеся данные из-за вчерашнего импорта
   → При загрузке видит предупреждение: "50k новых строк, но 2k уже в БД"
   → Может выбрать: "Пропустить дубли" или "Обновить существующие"
```

## User Journey #4: Дмитрий (Director) - "Утренний брифинг - 10 минут"

```
ПЕРСОНАЖ: Дмитрий, директор сети из 500 АЗС
ЦЕЛЬ: Получить обзор сети: ключевые KPI, проблемы, возможности
ВРЕМЯ: 10 минут
```

### Happy Path

```
1. ВХОД И ГЛАВНЫЙ DASHBOARD
   Заходит в систему → видит Dashboard
   ✅ Сразу видит: Средняя цена сети, Выручка за день, Процент выполнения плана

2. KEY METRICS
   КТО ЛИДИРУЕТ (Top 5 АЗС по выручке за день)
   КТО ОТСТАЕТ (Bottom 5 - низкая выручка или граф падает)
   АНОМАЛИИ (Красные флаги: цена < себестоимости, отсутствие данных)
   ✅ Все в одном окне, визуально понятно

3. СРАВНЕНИЕ С ПРОШЛЫМ ДНЕМ
   Видит стрелки: ↑ +2.3% выручка vs вчера, ↓ -0.4% объем топлива
   ✅ Быстрая оценка тренда

4. БЫСТРОЕ ДЕЙСТВИЕ
   Видит красный флаг на АЗС #127: "Цена критично низкая"
   Кликает на АЗС → видит: "Manager не онлайн, цена установлена вчера в 21:00"
   Может быстро послать SMS-уведомление manager'у
   ✅ Manager получает alert и поправляет в течение часа

5. ОТЧЕТЫ
   Может нажать "Построить отчет" → выбрать период, АЗС, метрики
   Видит готовый отчет через 30 сек
   Может поделиться с акционерами одной ссылкой
   ✅ Доступ к актуальным данным всегда
```

### Сценарий принятия решения

```
СИТУАЦИЯ: Директор видит что средняя цена упала на 1.2₽ за неделю (конкуренция)

ДЕЙСТВИЯ:
1. Нажимает "Анализ" для этого периода
2. Видит граф: как менялась цена у конкурентов
3. Видит корреляцию: наш объем упал на 15% когда мы снизили цену
4. Может нажать "Созвать совещание аналитиков" (отправляет уведомление Анне)
5. Анна подготавливает детальный анализ к следующему дню
6. На основе анализа принимается стратегическое решение о ценовой политике
```

# 📝 USER STORIES

## Must Have (Критичные)

### STORY #1: Вход и аутентификация (Priority: CRITICAL)

```markdown
**Как** любой пользователь (Manager, Analyst, Admin, Viewer)
**Я хочу** войти в систему используя логин и пароль
**Чтобы** получить доступ к функциям согласно моей роли

**Type:** Authentication  
**Estimation:** 3 points  
**Priority:** MUST HAVE

**Acceptance Criteria:**
- [ ] Поле Email и Password на форме входа
- [ ] При вводе неверных данных: "Логин или пароль неверный"
- [ ] После успешного входа: Redirect на Dashboard
- [ ] Сессия длится 24 часа, потом автоматический logout
- [ ] Кнопка "Забыли пароль?" работает (email с ссылкой восстановления)
- [ ] Правильное отображение в светлой и темной теме
- [ ] Работает на мобильных устройствах (responsive)
```

---

### STORY #2: Dashboard для Manager'а (Priority: CRITICAL)

```markdown
**Как** Manager (менеджер АЗС)
**Я хочу** увидеть рекомендации и KPI моей АЗС при входе
**Чтобы** быстро принять решение по ценам и увидеть статус

**Type:** Main Feature  
**Estimation:** 5 points  
**Priority:** MUST HAVE

**Acceptance Criteria:**
- [ ] Dashboard отображает (по умолчанию):
  - Текущая цена на топливо
  - Сравнение с конкурентами (выше/ниже на ₽X)
  - Рекомендация по цене (если есть)
  - Объем продаж за сегодня/вчера
  - Выручка за сегодня/вчера
  - Граф цены за последние 7 дней
- [ ] Рекомендации отображаются в порядке приоритета (URGENT → LOW)
- [ ] Каждая рекомендация это карточка с кнопкой "Применить" или "Подробнее"
- [ ] Load time Dashboard < 2 сек
- [ ] Данные автоматически обновляются каждые 15 минут (или можно нажать Refresh)
- [ ] Работает на мобильных и десктопе
```

---

### STORY #3: Применение рекомендации по цене (Priority: CRITICAL)

```markdown
**Как** Manager
**Я хочу** нажать одну кнопку и применить рекомендованную цену
**Чтобы** быстро реагировать на рынок без ручного ввода

**Type:** Core Action  
**Estimation:** 3 points  
**Priority:** MUST HAVE

**Acceptance Criteria:**
- [ ] На карточке рекомендации есть кнопка "Применить цену [X.XX₽]"
- [ ] При клике: подтверждение ("Вы уверены? Цена изменится с 55.5 на 54.9")
- [ ] После подтверждения: успешное уведомление "✓ Цена обновлена"
- [ ] Цена обновляется на табло АЗС в течение 30 сек
- [ ] История изменения цены логируется (кто, когда, какая была, какая стала)
- [ ] Если цена < себестоимости: кнопка заблокирована с объяснением
- [ ] Если Manager нет прав: кнопка заблокирована с предложением отправить заявку
```

---

### STORY #4: Просмотр рекомендаций с деталями (Priority: CRITICAL)

```markdown
**Как** Manager или Analyst
**Я хочу** увидеть подробный анализ для каждой рекомендации
**Чтобы** понять почему система предлагает это и уверенно принять решение

**Type:** Feature  
**Estimation:** 4 points  
**Priority:** MUST HAVE

**Acceptance Criteria:**
- [ ] При нажатии "Подробнее" открывается раздел с:
  - Названием правила (PRICE-001, TRAFFIC-002, и т.д.)
  - Описанием на русском ("Выравнивание цены с конкурентами")
  - Текущее значение vs рекомендуемое
  - Формула расчета (упрощенная для Manager'а)
  - Доверительность модели (R², если applicable)
```

# 🎯 ПРИОРИТИЗАЦИЯ

## Критерии приоритизации

### MUST HAVE (Критичные)
- Без этого система не работает
- Используется всеми пользователями
- Блокирует другие истории
- Требование клиента / бизнеса
- **Примеры:** Вход, Dashboard, Рекомендации, Импорт данных

### SHOULD HAVE (Важные)
- Значительно улучшает UX
- Используется большинством пользователей
- Может быть реализовано по планам
- Не блокирует другие истории
- **Примеры:** Аналитика, Мобильное приложение, Уведомления

### NICE TO HAVE (Приятные)
- Улучшает опыт
- Используется некоторыми пользователями
- Не критично для функциональности
- Может быть отложено
- **Примеры:** ML прогнозирование, Голосовой интерфейс, 1C интеграция
