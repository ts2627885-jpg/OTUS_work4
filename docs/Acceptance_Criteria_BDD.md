**Версия:** 1.0  
**Дата:** 7 октября 2026  
**Проект:** АЗС-Пульт  
**Формат:** BDD (Behavior Driven Development)  
**Инструмент для записи:** Gherkin syntax (для Cucumber, SpecFlow, Playwright)

---

# 📋 Введение в формат Given/When/Then

**Given** — Дано (предусловия, начальное состояние)  
**When** — Когда (действие пользователя)  
**Then** — То (ожидаемый результат, проверяемый исход)

**Пример:**
```gherkin
Сценарий: Успешный вход в систему
  Given я нахожусь на странице входа
  When я ввожу email "manager@azs.ru" и пароль "123456"
  And я нажимаю кнопку "Вход"
  Then я должен видеть Dashboard
  And в браузере должна быть сессия cookie
```

# 🔐 STORY #1: Вход и аутентификация

**Как** любой пользователь  
**Я хочу** войти используя логин и пароль  
**Чтобы** получить доступ согласно моей роли

## Сценарий 1.1: Успешный вход с верными данными

```gherkin
Given я на странице входа в систему
And поле "Email" пусто
And поле "Пароль" пусто
When я ввожу email "roman@azs.ru"
And я ввожу пароль "SecurePass123!"
And я нажимаю кнопку "Войти"
Then я должен быть перенаправлен на Dashboard
And я должен видеть мою роль "Manager" в профиле
And сессия должна быть активна на 24 часа
And в localStorage должен быть сохранен JWT токен
```

**Проверяемые условия:**
- [ ] URL изменился с /login на /dashboard
- [ ] Cookies содержит session_id с флагом HttpOnly
- [ ] localStorage['auth_token'] содержит валидный JWT
- [ ] JWT декодируется и содержит user_id, role, email
- [ ] Токен имеет iat (issued at) и exp (expiration) claims
- [ ] Page load time < 2 сек

- [ ] URL остался /login
- [ ] Сессия не создана
- [ ] В логах записано: попытка входа, время, IP, результат (FAILED)
- [ ] Если 3+ неверные попытки: временная блокировка (5 минут)
- [ ] Сообщение об ошибке НЕ содержит информацию "пароль неверный" или "email не существует" (по security)

## Сценарий 2.1: Загрузка Dashboard с корректными данными

```gherkin
Given я вошел как Manager АЗС #42
And в системе есть данные цен за последние 7 дней
And в системе есть данные конкурентов обновленные 15 минут назад
```

- [ ] Граф отображается за < 500ms

- [ ] Порядок сортировки: URGENT → HIGH → MEDIUM → LOW
- [ ] Цвета соответствуют дизайн-системе (красный #ef4444, оранжевый #f97316)
- [ ] Каждая карточка responsive (работает на мобильном)

# 💰 STORY #3: Применение рекомендации по цене

**Как** Manager  
**Я хочу** нажать одну кнопку и применить рекомендованную цену  
**Чтобы** быстро реагировать на рынок

---

## Сценарий 3.1: Применение валидной рекомендации

```gherkin
Given я вижу рекомендацию "Выравнивание цены на 54.90 ₽"
And текущая цена 55.50 ₽
And моя себестоимость 52.00 ₽
And рекомендуемая цена (54.90) > себестоимости (52.00) ✓
When я нажимаю кнопку "Применить цену 54.90 ₽"
Then должно появиться диалоговое окно подтверждения:
  "Изменить цену с 55.50 ₽ на 54.90 ₽?"
  "ДА" | "ОТМЕНА"
And если я нажимаю "ДА":
  - Цена должна измениться в системе
  - На табло АЗС должна отобразиться новая цена в течение 30 сек
  - Я должен видеть успешное сообщение "✓ Цена успешно обновлена"
  - Сообщение должно исчезнуть через 5 сек
  - В истории изменений должна появиться запись
```

**Проверяемые условия:**
- [ ] Диалог содержит старую и новую цену для ясности
- [ ] API запрос отправляется с поля Authorization header
- [ ] Цена обновляется в БД атомарно (ACID)
- [ ] Логируется: кто изменил, когда, старое значение, новое значение, рекомендация ID
- [ ] Табло получает сигнал обновить цену (по API или WebSocket)
- [ ] При отмене: ничего не меняется

---

## Сценарий 3.2: Блокировка при цене ниже себестоимости

```gherkin
Given я вижу рекомендацию "Снизить цену до 51.00 ₽"
And моя себестоимость 52.00 ₽
And рекомендуемая цена (51.00) < себестоимости (52.00) ❌
When я пытаюсь нажать кнопку "Применить"
Then кнопка "Применить" должна быть ОТКЛЮЧЕНА (disabled)
And вместо кнопки я должен видеть сообщение красным:
  "⚠️ Цена не может быть ниже себестоимости (52.00 ₽)"
And я не должен иметь возможность применить эту цену
```

**Проверяемые условия:**
- [ ] Кнопка имеет disabled атрибут (opacity 0.5, cursor not-allowed)
- [ ] Система никогда не позволит сохранить цену < себестоимости
- [ ] Валидация происходит на клиенте (UX) и на сервере (безопасность)

## Сценарий 6.1: Успешный импорт 50k строк

```gherkin
Given я администратор системы
And я на странице "Admin → Data Import"
And я имею файл "sales_2026_09.csv" (50k строк, 12MB)
When я нажимаю "Выбрать файл"
And я выбираю "sales_2026_09.csv"
Then система должна показать PREVIEW:
  - Первые 10 строк таблицы
  - Обнаруженные колонки: date, price, quantity, azs_id, ...
  - Количество строк: 49,987 (все строки посчитаны)
And я должен видеть валидацию: "✓ Файл валиден"

When я нажимаю "Импортировать"
Then система должна показать прогресс-бар:
  "Обработано: 0/49,987 строк (0%)"
And прогресс должен обновляться каждые 5 сек:
  5,000 строк (10%)
  10,000 строк (20%)
  ...
  49,987 строк (100%)

When импорт завершен:
Then я должен видеть отчет:
  "✓ Импорт завершен успешно
   Успешно импортировано: 49,987 строк
   Ошибок: 13 строк (детали в файле ошибок)
   Время выполнения: 45 сек
```

- [ ] Блокировка осторожная (не навсегда, временно)
