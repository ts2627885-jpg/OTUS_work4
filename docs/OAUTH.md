# Вход через OAuth2: Google и Яндекс ID

Вход через внешнего провайдера добавлен рядом с входом по логину и паролю. Провайдер включается, только если для него заданы `CLIENT_ID` и `CLIENT_SECRET`. Без них кнопки на странице входа не показываются, и всё работает как раньше.

## Как устроено

1. Кнопка «Войти через …» ведёт на `/api/auth/oauth/<provider>/start`.
2. Сервер создаёт случайный `state`, сохраняет его в подписанной HttpOnly-cookie и перенаправляет на страницу входа провайдера.
3. Провайдер возвращает пользователя на `/api/auth/oauth/<provider>/callback?code=…&state=…`.
4. Сервер проверяет `state` (cookie и параметр должны совпасть), меняет `code` на токен у провайдера и получает профиль.
5. Пользователь ищется по паре «провайдер + идентификатор у провайдера». Если её нет, создаётся новый пользователь с ролью `viewer` и случайным паролем, который никто не знает.
6. Сервер выдаёт тот же JWT, что и при обычном входе, и перенаправляет на `/login#oauth_token=…`. Фронтенд читает токен из фрагмента адреса и сразу стирает его из адресной строки.

Ошибки возвращаются тем же способом: `/login#oauth_error=<код>`. Коды описаны в `frontend/src/views/LoginView.vue`.

## Защита

- **CSRF при возврате:** `state` подписан HMAC и привязан к cookie браузера. Подменённый или чужой `state` отклоняется.
- **Почта:** для Google требуется `email_verified = true`, для Яндекс ID — адрес `default_email`. Без подтверждённой почты вход не разрешается.
- **Существующие учётки не связываются автоматически.** Если почта уже занята локальной учёткой, вход отклоняется с сообщением «Почта уже используется». Иначе учётку администратора можно было бы захватить через провайдера с той же почтой.
- **Токен не попадает в адрес запроса и журналы:** он во фрагменте, а фрагмент сервер не получает.
- **Отключённая учётка** не получает токен, даже если провайдер подтвердил вход.

## Что нужно сделать вам

### 1. Google Cloud Console

1. Создайте проект и откройте **APIs & Services → OAuth consent screen**. Тип пользователей — External, укажите название приложения и почту поддержки. Области: `openid`, `email`, `profile`.
   Пока приложение в статусе Testing, войти смогут только добавленные **Test users**.
2. **APIs & Services → Credentials → Create credentials → OAuth client ID → Web application.**
3. В **Authorized redirect URIs** добавьте:
   - `https://otuswork5.vercel.app/api/auth/oauth/google/callback`
   - для локальной разработки: `http://localhost:3000/api/auth/oauth/google/callback` (Vite проксирует `/api` на backend, поэтому адрес — порт фронтенда)
4. Скопируйте **Client ID** и **Client secret**.

### 2. Яндекс ID

1. Откройте https://oauth.yandex.ru/client/new и выберите **Веб-сервисы**.
2. Укажите название и **Callback URI**: `https://otuswork5.vercel.app/api/auth/oauth/yandex/callback`
3. В правах доступа выберите `login:email` (почта) и `login:info` (логин и имя).
4. Сохраните и скопируйте **ID** и **Пароль** (Client secret).

### 3. Переменные окружения

Добавьте в Vercel (проект `otus_work5` → Settings → Environment Variables) или в локальный `backend/.env`:

| Переменная | Значение |
|---|---|
| `OAUTH_PUBLIC_URL` | `https://otuswork5.vercel.app` (без «/» на конце); локально — `http://localhost:3000` |
| `OAUTH_STATE_SECRET` | случайная строка не короче 32 символов |
| `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET` | из Google Cloud Console |
| `YANDEX_CLIENT_ID`, `YANDEX_CLIENT_SECRET` | из Яндекс ID |

Значение `OAUTH_STATE_SECRET` можно сгенерировать командой:
```bash
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

Если задан только один провайдер, второй кнопки не будет.

### 4. Миграция базы

Таблица `oauth_accounts` создаётся миграцией `018_oauth_accounts.sql`. Миграция выдаёт права роли `azs_app`, если она существует. Примените её к продакшен-базе обычным порядком миграций (`npm run migrate` из `backend/` с `DB_*`, указывающими на продакшен), либо выполните файл в SQL Editor.

### 5. Проверка

1. Откройте страницу входа: должна появиться кнопка провайдера.
2. Войдите через провайдера под тестовым пользователем (для Google — из списка Test users).
3. Новый пользователь появится в таблице `users` с ролью `viewer`, а связка — в `oauth_accounts`.
4. Вход с почтой, уже занятой локальной учёткой, должен показать сообщение «Почта уже используется».

## Ограничения

- Пока приложение Google в статусе Testing, вход доступен только для тестовых пользователей. Перевод в Production требует проверки Google.
- Роль новых пользователей — `viewer`. Повышение делает администратор в разделе «Администрация».
- Связать уже существующую учётку с провайдером пока нельзя: нужна отдельная функция в профиле.
- Ограничение попыток для callback не добавлено: провайдер сам ограничивает обмен кодов.
- Обмен `code` на токен и получение профиля проверены только на отказе (неверный код, неверный `state`). Успешный вход с настоящим провайдером ещё не проверен: для этого нужны учётные данные из шагов 1–2.
