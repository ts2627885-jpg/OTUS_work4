# Формулы правил рекомендаций

Правила считаются в `backend/src/services/rules.service.ts` (станции и сеть) и
`backend/src/services/rules-extra.service.ts` (конкуренты, трафик, акции, магазин). Пороги хранятся в `app_settings`
(значения по умолчанию — `DEFAULT_RULE_SETTINGS` в `settings.service.ts`). Дата расчёта — последний день с известной
ценой (`asOf`).

## Общие обозначения

| Символ | Значение |
|---|---|
| p | наша цена, ₽/л (последняя известная за `price_window_days` = 30 дн.) |
| p_comp | медиана последних наблюдений цен конкурентов по брендам за `comp_window_days` = 14 дн. |
| V₇ | средний дневной объём за последние 7 дней, л/день |
| ε | эластичность спроса по цене (см. раздел «Эластичность») |
| t | t-статистика коэффициента ε |

Функция медианы и среднего — обычные. Округление: до 2 знаков для цен, до рублей для эффектов.

## Эластичность

**Оценка по сети (панель).** Регрессия ln(объём) на ln(цену) с контролями:

ln(V) = b·ln(p) + эффект станции + день недели + праздник + месяц + ε

- Окно: `elasticity_days` = 365 дней.
- Нерабочие дни станции исключаются: суммарный объём за день меньше 10% медианного дневного объёма станции.
- Минимум наблюдений: 200 для сети, 120 для одной станции.
- Эластичность ε = b. Значима, если |t| ≥ 2 и b < 0.
- Станционная оценка берётся, если она значима; иначе используется сетевая оценка.
- Если ни одна оценка не значима, эффект считается по точечной отрицательной оценке и помечается «низкая надёжность».

Оценка выполняется методом нормальных уравнений с обращением матрицы (`invert`). Результаты кэшируются по версии данных
(дата и число строк `azs.fuel_daily`).

## Станционные правила (rules.service.ts)

### PRICE-001 — выравнивание цены с рынком

- **Разрыв:** gap = p − p_comp.
- **Срабатывание:** |gap| > `price_gap_min` (0,5 ₽).
- **Приоритет:** URGENT, если |gap| > `price_gap_urgent` (1,5 ₽), иначе HIGH.
- **Целевая цена:** p_comp − 0,1, если gap > 0; иначе p_comp + 0,1.
- **Эффект:** |gap| × V₇ × |ε|, ₽/день. Округляется до рублей.
  Это первое приближение объёмного эффекта: ΔV ≈ V·ε·Δp/p, и ΔV·p = V·ε·Δp.
- Если ε не определена, эффект не считается, а действие превращается в ориентир, а не в указание.

Пример: разрыв 2,0 ₽, V₇ = 1000 л/день, ε = −0,5 → эффект 1000 ₽/день. Проверяется тестом
`tests/unit/services/rules.effect.test.ts`.

### PRICE-002 — избыточная премия к конкурентам

- **Условия:** p > p_comp и падение объёма V₇ к предыдущим 7 дням ниже `premium_drop_pct` (−5%).
- **Изменение объёма:** (V₇ / V₇_prev − 1) × 100%.
- **Приоритет:** HIGH, если p выше максимума конкурентов, иначе MEDIUM.
- **Действие:** снизить цену на p − p_comp ₽ или запустить промо.

### PRICE-003 / PRICE-005 — не реализованы

Правила PRICE-003 (оптимальная цена) и PRICE-005 (проверка ниже себестоимости) требуют себестоимости, которой в данных
нет. Они попадают в список «не рассчитано» с причиной.

### PRICE-004 — сводка по незначимым парам

Пары «станция + топливо», где эластичность не значима (при ≥ 30 наблюдениях), собираются в одну рекомендацию. Шаг
A/B-теста — `ab_step` (0,5 ₽).

### COMP-001 — конкурент снизил цену

- **Снижение цены бренда:** drop = p_cur − p_before ≤ `comp_drop_min` (−0,4 ₽). Сравнение с наблюдением за 3–14 дней до
  текущего.
- **Реакция объёма:** reaction = V₃ / V₇' − 1, где V₃ — средний объём за последние 3 дня, V₇' — за дни 3–10 назад.
  Срабатывание: reaction ≤ `comp_reaction_min` (−30%).
- **Приоритет:** URGENT.
- **Действие:** снизить цену на 0,20 ₽ или на 0,35 ₽ (ориентировочно возвращает 70% и 95% объёма).

### TRAFFIC-002 — растущий трафик станции

- **Тренд:** линейная регрессия легковых машин по дням (окно 28 дн., минимум 14 точек).
- **Срабатывание:** наклон > `traffic_slope_min` (0,5 авт./день).
- **Приоритет:** MEDIUM.

## Сетевые правила (rules.service.ts)

- **NET-PRICE-<вид топлива>** (правило PRICE-003) — чувствительность спроса по сети к цене: срабатывает при значимой сетевой эластичности.
- **NET-TEST-<вид топлива>** (правило PRICE-004) — сетевой тест цены: предлагается, если сетевая эластичность не значима.
- **NET-TRAFFIC** (правило TRAFFIC-002) — изменение легковых машин по сети за 28 дней к предыдущим 28:
  change = (cur / prev − 1) × 100%; срабатывает при |change| ≥ 5%. Приоритет MEDIUM при росте, HIGH при падении.
- **PROMO-003-NETWORK** — частота акций: число активных акций за 30 дней (`promo_limit` = 2). HIGH, если акций не меньше
  порога, иначе LOW.

## Правила конкурентов (rules-extra.service.ts)

### COMP-002 — конкуренты повышают или снижают цену

- **Ряд:** средние цены по неделям за 120 дней, минимум 12 недель.
- **Тренд:** наклон регрессии по неделям, R² > 0,5, относительный наклон |slope| / p̄ ≥ 0,5% в неделю.
- **Надёжность:** 95% доверительный интервал наклона не содержит 0 (бутстрэп с фиксированным зерном).
- **Согласованность:** минимум два бренда с одинаковым направлением и не меньше половины брендов.
- **Приоритет:** MEDIUM при росте цен, LOW при снижении.

### COMP-003 — чувствительность к ценам конкурентов

- **Модель:** ln(V) = b·ln(p_comp) + контроль дня недели. Окно — 365 дней, сглаживание p_comp — среднее за 14 дней.
- **Срабатывание:** значимо (|t| ≥ 2, b < 0) и b < −0,8.
- **Приоритет:** HIGH при b < −1,5, иначе MEDIUM.
- **Проверка обратной причинности:** то же с лагом 7 дней. Если с лагом знак отрицательный, это реакция на цену конкурента.

## Правила трафика (rules-extra.service.ts)

- **TRAFFIC-001 — падение доли станции в сети:** доля станции в объёме сети за последние 28 дней сравнивается с
  предыдущими 28. Срабатывание при изменении доли ≤ −8%.
- **TRAFFIC-003 — аномально низкий трафик:** среднее легковых за 28 дней < 20% медианы станций → HIGH, «проверить
  датчики». Если данных меньше 25 дней из 28 → MEDIUM, «пропуски в данных».

## Прочие правила (rules-extra.service.ts)

- **PROMO-002 — слабые дни недели для акций:** средний объём дня недели < 85% среднего по неделе за 180 дней.
- **SHOP-001 — ABC-анализ магазина:** товары магазина за 365 дней, сортировка по выручке.
  - A: товары, накопленная доля выручки до которых (не включая сам товар) меньше 80%;
  - B: до 95%;
  - C: остальное.

## Правила без расчёта

Следующие правила выводятся в раздел «не рассчитано» с причиной, потому что в данных нет нужных полей:
PRICE-003, PRICE-005 (себестоимость), PROMO-001 (стоимость акции и прирост объёма), SHOP-002 (маржа товаров),
SHOP-003 (чеки), SHOP-004 (ассортимент конкурентов).
